# NetPrintServer 开发文档

| 项目 | 内容 |
|---|---|
| 版本 | 与程序 v1.1.1 对应 |
| 语言/工具链 | Go 1.20.14（**必须 ≤1.20**，1.21 起不再支持 Windows 7） |
| 唯一第三方依赖 | `golang.org/x/sys v0.15.0`（Windows 服务与系统调用） |
| 构建环境 | Linux（交叉编译 Windows 目标），无 CGo |
| 日期 | 2026-10-07 |

---

## 1. 技术选型与理由

| 决策 | 选择 | 理由 |
|---|---|---|
| 语言 | Go | 交叉编译出**单文件无依赖** exe；并发模型适合多端口监听；标准库含 net/http 与模板 |
| 工具链版本 | Go 1.20.14 | 1.21 起放弃 Windows 7；1.20 是最后支持 Win7 的版本 |
| 第三方依赖 | 仅 x/sys | 最小化供应链；GUI 框架（Walk/Fyne）需要 CGo 或不支持 Win7，故图形化配置采用**网页端** |
| 打印转发 | winspool.dll 原生 API | 与 Windows 打印后台无缝衔接（排队/驱动/状态全继承），数据零转换 |
| 图形化配置 | 网页端 + 登录鉴权 | 任意机器可管理、无跨编译 GUI 代价、天然可做鉴权与 CSRF 防护 |
| 服务模型 | Windows 服务（SCM） | 开机自启、无窗口、崩溃可由 SCM 拉起 |
| 测试策略 | Linux 上以 file 后端跑全链路 | winspool 无法在 Linux 执行 → 抽象 `Backend` 接口，协议层/配置层/网页层全部可测 |

## 3. 架构与数据流

### 3.1 打印链路

```
客户端 Windows                                服务器主机
┌─────────────────────┐                 ┌──────────────────────────────────────┐
│ 真实驱动渲染 ESC/P   │   TCP:9100      │ RAWListener.handle                  │
│ 标准 TCP/IP 端口 ───┼───────────────► │   Backend.OpenJob → StartDocPrinter │
└─────────────────────┘   (RAW 字节流)  │   WritePrinter 流式写入 → EndDoc    │
                                        │        │                            │
┌─────────────────────┐   TCP:515       │        ▼                             │
│ LPR 端口监视器 ─────┼───────────────► │ Windows 打印后台 (spooler) 排队      │
└─────────────────────┘  (RFC1179)      │        │                            │
                                        │        ▼                             │
                                        │ 本机驱动 → USB/LPT → LQ-630K 出纸   │
                                        └──────────────────────────────────────┘
```

要点：服务端**不解析不转换**打印数据（数据类型 RAW）；排队、驱动、状态全部交给 spooler。

### 3.2 配置链路（热应用 + 回滚）

```
配置页表单 ──fetch POST /api/config（Cookie + X-NPS-Auth + 同源 Origin）
   │
   ├─► 服务端：payload → 拷贝当前 Config → 合并 → validateConfig → 写 config.json
   │        └─► 立即应答 {ok:true}（此时旧监听还活着）
   └─► 400ms 后异步 Manager.Reload(newCfg)
             ├─ Stop()：cancel ctx → 关闭全部监听（含状态页自身）
             ├─ 换 cfg/backend → Start()：重新绑定全部端口
             ├─ 成功 → 配置生效，写「上次应用」
             └─ 失败 → 回滚：恢复旧 cfg/backend、先写回 config.json、再 Start 旧配置
```

关键点：**先应答再重启**（否则响应发不出去）；**回滚时先恢复文件再恢复监听**（避免读到半套配置）；失败与成功都记录到 `netprintserver.log` 并显示在配置页顶部。

### 3.3 打印机选择（三种模式）

```
枚举本机打印机 ──► 手动 bindings？ ──是──► 强制纳入（可覆盖任何规则）
                     │否
                     ▼
   selection_mode = selected ──► 只要出现在 selected_printers 里（按名不区分大小写）
                   = all      ──► 全部纳入
                   = auto     ──► printerFilter：端口前缀排除 + 名称/驱动关键字排除
                                  （include_keywords 非空时先做白名单）
                     │
        纳入 → 分配端口（历史粘性优先，其次 start_port 起最小空闲端口）
        跳过 → 记入 skipped（带原因），并从历史分配中清理
```

## 4. 关键设计决策（ADR 摘要）

| # | 决策 | 备选 | 取舍原因 |
|---|---|---|---|
| 1 | 后端抽象 `Backend` 接口 + file 后端 | 直接写 winspool | 否则无法在 Linux 做任何自动化测试；file 后端同时充当「字节是否到达」的排障工具 |
| 2 | 端口分配持久化到 `config.state.json` | 每次重新分配 | 客户端配置的是 IP:端口，端口漂移=客户端全挂 |
| 3 | 监听器失败作为 `Start` 的错误返回 | 只打日志 | 热应用回滚需要明确的成功/失败信号 |
| 4 | 会话存储挂在 Manager（`adminOnce`）而非 WebServer | 跟随 WebServer 创建 | 热应用会重建 WebServer，会话不能因此失效 |
| 5 | winspool 缓冲区字符串读取**必须**做地址边界校验 | 直接 `unsafe.Slice` 扫描 | Windows 可能返回异常布局，野指针会直接打崩进程（v1.0.0 事故根源之一） |
| 6 | `bind_ip` 时同时监听 127.0.0.1 | 只绑指定地址 | 限制对外暴露不应牺牲本机可达性（v1.1.1 事故） |
| 7 | 状态页公开只读、配置台鉴权 | 全站鉴权 | 车间现场人员需要随时看打印机状态；改动风险只存在于配置台 |
| 8 | 源码级回归守卫测试 | 仅靠人工 review | EnumPrinters 层级这类「一个数字写错全盘崩溃」的缺陷必须机器兜底 |

## 5. Windows API 调用清单与踩坑记录

### 5.1 调用清单（全部在 `winspool_windows.go`）

| API | 用途 | 关键参数 |
|---|---|---|
| `OpenPrinterW` | 取打印机句柄 | `PRINTER_DEFAULTS{DesiredAccess: PRINTER_ACCESS_USE(0x8)｜ADMINISTER(0x4)，降级到 USE}` |
| `ClosePrinter` | 关闭句柄 | — |
| `StartDocPrinterW` | 开始作业，返回 JobId | Level=1，`DOC_INFO_1{pDocName, pOutputFile:"", pDatatype:"RAW"}` |
| `WritePrinter` | 流式写入字节 | — |
| `EndDocPrinter` | 提交作业 | — |
| `EnumPrintersW` | 枚举打印机 | Flags=`PRINTER_ENUM_LOCAL(0x2)\|CONNECTIONS(0x4)`，**Level=4**（PRINTER_INFO_4） |
| `GetPrinterW` | 打印机详情（端口/驱动/状态/作业数） | Level=2（PRINTER_INFO_2） |
| `EnumJobsW` | 队列作业状态 | Level=1（JOB_INFO_1） |
| `SetJobW` | 删除未完成作业 | Level=0、pJob=NULL、Command=`JOB_CONTROL_DELETE(5)` |
| `MultiByteToWideChar` | netsh 输出按 OEM 代码页转 UTF-8 | CP_OEMCP=1 |
| `IsUserAnAdmin` (shell32) | 提权判断 | — |

### 5.2 结构体布局（已与 Windows SDK 头文件逐字段核对，并用 gcc 编译 C 结构比对偏移/大小）

```
PRINTER_INFO_2W (x64: 136 字节) —— 注意首成员是 pServerName！
  pServerName pPrinterName pShareName pPortName pDriverName pComment pLocation
  pDevMode pSepFile pPrintProcessor pDatatype pParameters pSecurityDescriptor
  Attributes Priority DefaultPriority StartTime UntilTime Status cJobs AveragePPM

JOB_INFO_1W (x64: 96 字节) —— 尾部有 SYSTEMTIME Submitted(16 字节)，中间没有 StartTime/UntilTime
  JobId pPrinterName pMachineName pUserName pDocument pDatatype pStatus
  Status Priority Position TotalPages PagesPrinted Submitted

PRINTER_INFO_4W (24 字节): pPrinterName pServerName Attributes
DOC_INFO_1W  (24 字节): pDocName pOutputFile pDatatype
```

验证方式：`gcc layout_check.c` 输出 C 侧 sizeof/offsetof 与 Go 侧 `unsafe.Sizeof/Offsetof` 对比一致。

### 5.3 踩坑记录（全部已修复并加回归测试）

| # | 现象 | 根因 | 修复 |
|---|---|---|---|
| 1 | `install/status/printers` 启动即 `unexpected fault address 0xffffffffffffffff` | `EnumPrintersW` 的 **Level 传了 0**，返回缓冲区按 PRINTER_INFO_4 解析 → 指针字段读到垃圾地址 | Level 改 4；守卫测试 `TestEnumPrintersLevel` 断言 Level 非 0 |
| 2 | 同上（崩溃面） | 缓冲区字符串读取无边界校验 | 统一改为 `utf16InBuffer(ptr, low, high)`：指针不在缓冲区范围内直接跳过；守卫 `TestWinspoolBufferReadsAreBounded` |
| 3 | `diag` 报 `SetJob 未找到` | winspool.drv 只导出 `SetJobA/SetJobW`，没有裸 `SetJob` | 改 `SetJobW`；守卫 `TestWinspoolUsesSetJobW` |
| 4 | 防火墙规则失败：`'enabled' 不是有效的参数` | netsh 参数是 `enable=yes`，不是 `enabled=yes` | 参数构造抽到 `firewall.go` 平台无关函数；守卫 `TestFirewallArgsUseEnableNotEnabled` |
| 5 | Windows 真机 10 台打印机中混入 PDF/传真/虚拟绘图仪 | 无筛选 | `printerFilter`（关键字+端口前缀）+ 真实枚举数据回归测试 |
| 6 | install 显示「未发现本机打印机」（明明枚举到 10 台） | `resolveBindings` 的返回值没有写回 `Manager.bindings` | 函数内直接写回 |
| 7 | 状态页 IP 显示 169.254.x.x | IP 未排序，取了第一个 | 过滤链路本地 + 内网优先 + 虚拟网卡降级（`ipSortKey`） |
| 8 | 冒烟中 web 页面 EOF | `ipSortKey` 对 4 字节 IPv4 用 `ip[12]` 索引 → panic（Windows 上会启动即退） | 改用 `ip.To4()` 后按 `[0]/[1]` 取字节；`TestIPSortKeyPrefersRealLAN` |
| 9 | 设 `bind_ip` 后 `127.0.0.1` 无法访问 | 只绑了指定地址，回环无人监听 | `bindPort`：指定网卡时额外监听 127.0.0.1（主地址失败仍报错，回环失败仅警告）；`TestBindIPKeepsLoopbackAccess` |
| 10 | netsh 中文输出乱码 | 控制台 OEM 代码页字节直塞日志 | `MultiByteToWideChar(CP_OEMCP)` 转 UTF-8 |

## 6. 平台适配

通过构建标签分离平台代码：

- `*_windows.go`（`//go:build windows`）：`winspool_windows.go`、`service_windows.go`
- `platform_other.go`（`//go:build !windows`）：桩实现，使 Linux 能编译、运行测试
- 其余文件平台无关；netsh 参数、筛选器、配置校验刻意放在平台无关文件中，以便单测

## 7. 构建流程

```bash
# 工具链：Go 1.20.14（勿用 1.21+，会失去 Win7 兼容）
export GOPROXY=https://goproxy.cn,direct   # 国内网络代理

gofmt -w .                                  # 格式化
go vet ./...                                # 静态检查
GOOS=windows go vet ./...                   # Windows 目标静态检查
go test ./... -count=1                      # 全量测试（36 条）

GOOS=windows GOARCH=amd64 go build -ldflags "-s -w" -o netprintserver.exe .
GOOS=windows GOARCH=386   go build -ldflags "-s -w" -o netprintserver-x86.exe .
```

产物：x64 exe（约 7.2 MB）、x86 exe（约 7.0 MB），`file` 确认 `PE32+ x86-64` / `PE32 Intel 80386`。

## 10. 扩展开发指引

**新增一个配置项**：`config.go` 加字段与默认值（`applyDefaults`）→ `validateConfig` 加校验 → `webadmin.go` 的 `configPayload` + 合并逻辑 → `webadmin_pages.go` 表单加控件与 JS `collect()` 字段 → `e2e`/`webadmin` 测试 → 更新《03-接口文档》schema 表。

**新增一个 HTTP 接口**：在 `webadmin.go`（需鉴权）或 `webui.go`（公开）注册路由 → 遵循统一响应 `{ok, note/error}` → 写测试断言状态码与副作用 → 更新接口文档。

**新增一个打印协议**：仿照 `rawserver.go` 写 `xxxserver.go`（实现 `Serve(ctx, ln)`）→ 在 `manager.go` 的 `Start` 里 `bindPort` + 挂 goroutine → 配置项开关 → 测试 → 接口文档加协议章节。

**改动 winspool 调用**：必须对照 SDK 头文件核对结构体与常量（可用 mingw-w64/winspool.h + gcc sizeof 比对），并补充 `winspool_guard_test.go` 守卫。

## 11. 交付与发布流程

1. `gofmt` + 双平台 `go vet` + `go test ./...` 全绿；
2. 交叉编译两个 exe，`file` 校验 PE 格式；
3. 更新 `README.md` 版本号与变更点、同步 `docs/`；
4. 组装发布包（`NetPrintServer-v<版本>.zip`：exe×2、bat×2、README、client 脚本）；
5. 组装归档包（本包：`src/` 源码 + `docs/` 文档 + `dist/` 编译产物 + `client/` 脚本）；
6. 记录 sha256 交付。
